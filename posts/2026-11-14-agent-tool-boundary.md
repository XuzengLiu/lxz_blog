假设我们给 Agent 接一个查任务状态的工具。先把工具当普通函数来设计：调用者给什么，函数返回什么，失败后该怎么做？

## 最小约定

- 输入：一个非空的任务 ID。
- 成功：返回任务 ID 和允许的状态，例如 `running`。
- 任务不存在：返回明确的 `not_found`，让 Agent 询问用户是否输错。
- 查不到结果：如果上游超时，就告诉用户暂时无法确认，不把超时当成任务失败。

一次成功的返回可以长这样：

```json
{
  "ok": true,
  "task_id": "task-42",
  "status": "running"
}
```

## 用失败场景验收

分别模拟空 ID、未知 ID 和查询超时。观察最终回答有没有区分三种情况，以及 Agent 会不会凭空补上一个任务状态。这样可以先检查工具边界，再决定要不要接入更复杂的流程。
